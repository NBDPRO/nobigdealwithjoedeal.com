# Accessibility audit: Daily Success day page, Workout Coach, Call Center (2026-10-23)

Scope: the tracker day page and the coach card / logger (`docs/pro/daily-success/`), and the CRM Call Center
(`docs/pro/js/call-center-view.js`, `call-center-filters-logic.js`). A real VoiceOver pass can only be done on Jo's
iPhone, so this audit did everything a browser can prove, and ends with a checklist for the rest.

Not touched on purpose: the theme / appearance picker (`#nbd-picker-modal`, owned by the accent-picker work) and the
Progress tab (owned by measurements-photos). Both still have unnamed controls, listed under "Left open".

## How it was done

- `scripts/a11y-audit-browser.js` drives the tracker and the Call Center in headless Chromium with the **keyboard only** and
  asserts the result (22 checks). It stubs the sign-in module and every external host; nothing leaves the machine.
  It needs Playwright (not in CI): `node scripts/a11y-audit-browser.js`. Negative control: with `a11y-ui.js` removed, 9 of
  the 22 fail.
- `tests/a11y-audit-2026-10-23.test.js` (node bucket, 70 checks) runs the pure rules for real and pins the markup and wiring
  with comments stripped. A 19-mutation run killed every mutant after four weak pins were tightened (the first run left
  4 survivors: `restSay` call guarded off, `state.refocus` renamed, the toast `__fresh` flag flipped, the inert-before-focus
  ordering).
- The element dump used to find the problems: every `button, input, select, textarea, a, [data-action]` on the page, its
  accessible name (aria-label, label, text, title, placeholder), and whether it is a real control.

## Findings and fixes

| # | Where | Finding (before) | Fix |
|---|---|---|---|
| 1 | Day page accordion | The section headers were `<div data-action="toggle-section">`: no keyboard, no focus, no state. 10 sections unreachable without a mouse. | `role=button`, `tabindex=0`, Enter / Space, `aria-expanded` kept in step with `.collapsed`, `aria-controls` to the body, body is a labelled `region` (`a11y-ui.js`). |
| 2 | Page tabs, dashboard rows | `div.tab`, `div.tplus`, `div.prd`, `.best` were clickable divs. The `×` and `+` had no name. | Same role / tabindex / key handling. `aria-current="page"` on the open tab, "New page", "Delete page OCT 22". |
| 3 | Topbar | `🔍 🎨 ⚙️ 📖 ×` buttons had only a `title` (read as an emoji name). Search box and rename box had only a placeholder. | Explicit `aria-label`s in `index.html`; search is `type=search`. Controls added later by JS take their title / placeholder / neighbouring label. |
| 4 | Habit dots | Bare empty `<span>`s in a table, 7 per habit, no name, no state. | Named "&lt;habit&gt;, &lt;weekday&gt;" with `aria-pressed`. |
| 5 | Priority / gratitude boxes | Textareas with no label (no placeholder either). | "Priority 1-3", "Gratitude 1-3". |
| 6 | Every sheet and modal (Coach, Weekly review, Money, Import history, Rename, Delete, Onboarding, Welcome) | Some had `role=dialog`, none had `aria-modal`, none moved focus in, trapped Tab, or returned focus. The page behind stayed reachable by swipe. | One layer: `role=dialog` + `aria-modal` + a name, page behind `inert`, Tab wraps inside, focus in on open and back to the opener on close (even when the opener was redrawn), Escape closes sheets that did not handle it. |
| 7 | Coach logger | Every tap redraws the whole sheet, so focus fell to `<body>` after each set. | Focus is put back on "the same button" (`data-coach-action` + indexes) after a redraw. |
| 8 | Coach rest timer | `#wcRest.innerHTML` was rebuilt **every second**, so the Skip button lost focus every second (a keyboard / VoiceOver user could not press it). Nothing was announced. | The text is its own `role=timer` span; the button is built once. One persistent polite live region speaks three things per rest: "Rest 1:30", "10 seconds left", "Rest over. Go." (`restSay`, pure and tested). |
| 9 | Coach chips, set check, gear | `.on` was colour only. | `aria-pressed` on all seven toggle chips and the set check, `aria-expanded` on the gear, ready-check rows are named groups, plate chips say "45 lb plate", the "x ✕" chip says "Stop avoiding &lt;lift&gt;". |
| 10 | Toasts (`/pro/js/toast.js`, shared) | No live region: a screen reader never heard "Saved ✓". | Container is `role=status` / polite; error toasts are `role=alert`; the first toast of a page is added a beat after its region exists. The tracker's `#nbd-toast` line is a polite region too. |
| 11 | Landmarks | No `main`, no `nav`, no `h1`, no `banner`. | `banner` (topbar), `navigation` "Pages", `main`, `search`, and "DAILY SUCCESS" is the `h1`. |
| 12 | Focus visibility | Several inputs set `outline: none` and only tint their background; no `:focus-visible` anywhere. | 2 px ring on everything focusable (last `<style>` block, `!important` so a theme cannot remove it). |
| 13 | Reduced motion | None on the tracker (transitions, smooth scroll). | `@media (prefers-reduced-motion: reduce)` in the last `<style>` block; the two `behavior:'smooth'` scrolls ask `scrollBehavior()`. |
| 14 | Call Center tabs | `role=tablist` / `tab` with no panel, no `aria-controls`, every tab a tab stop, no arrow keys. | Real tabs: ids, `aria-controls="ccPanel"`, roving tabindex, ArrowLeft/Right/Up/Down/Home/End, list is a `tabpanel` labelled by the active tab. |
| 15 | Call Center redraw | `render()` replaces the whole view on every click, so focus fell to the top after a chip, a date or a tab. Only the search box was restored. | Focus is restored to the same control (or the list panel if the control is gone, e.g. a call was Handled). |
| 16 | Call Center actions | Dozens of identical "▶ Play" / "✓ Handled" / "📌 Promise" buttons, emoji read aloud, no clue whose. | "Play for Dana Smith", "Handled for Dana Smith" (glyph dropped, person named). Status lines under each card are `role=status`. |
| 17 | Call Center results | The "Showing N" line was a `role=status` that was destroyed and recreated on every render (never announced). | One persistent polite line: "Showing 3 people, Needs attention, Today". Recording `<audio>` is named. |
| 18 | One-at-a-time deck (`triage-deck.js`, opened from the Call Center) | `aria-modal` with no name, no focus move, no focus return. | Named, focus moves in, opener refocused on close. |

## Re-audit after main moved (same night)

Re-checked the surfaces that landed while this PR was open (accent picker, Progress measurements / photos, Call Center status chips):

- **Call Center status chips**: built through the same `chipBtn` (aria-pressed, 44 px) in a named "Status" group; focus restore covers them. No change needed.
- **Accent swatches**: named radiogroup, `aria-checked`, a label per swatch. Fine. Gap left open: no arrow-key roving between swatches (each is a tab stop).
- **Progress measurements / photos**: site and pose chips had no `aria-pressed` (unit chips did), every photo had an identical "Delete" button, and a tap that redraws the panel dropped focus. Fixed: `aria-pressed` on all three chip rows, "Delete <pose> photo from <date>", and the tracker layer puts focus back on the same button after such a redraw.

## Left open (named, not fixed here)

- **Theme / appearance picker** (`#nbd-picker-modal`): `✕` close buttons with no name, `npm-search` and five colour pickers
  with no label, picker tabs are buttons without `aria-selected`. Owned by the accent-picker session; pass this list to it.
- **Triage deck background** is not `inert` (focus moves in and returns, but a swipe can still leave the dialog), and Escape
  is ignored while focus is in the deck's text box. Both are in a file shared with other pages.
- **Section titles are button names**, not headings, so VoiceOver's headings rotor lists only the h1 and the dialogs' own h3s.
  The accordion pattern would wrap the button in a heading; skipped to avoid reflowing the card markup.
- **Colour contrast was not measured** here. The muted text on the dark themes (`--muted`, `.wc-hint`, `.pc-meta`) is the
  likely weak spot; run a contrast check per theme once the accent picker lands.
- **Food search, health shortcut, Progress** sheets and the Money / Review sheets' *internal* controls were only covered by
  the generic layer (names, dialog, focus), not walked control by control.
- The Call Center has no animations, so there was nothing to reduce; the dashboard's own CSS carries its reduced-motion rules.

## Checklist for Jo: the real VoiceOver pass (iPhone, Settings > Accessibility > VoiceOver)

Do it once on the installed app, Daily Success first, then the CRM Call Center. Note anything that sounds wrong.

1. **Day page.** Swipe right through the top bar. Each icon should say what it does ("Search all pages", "Appearance", not
   "magnifying glass"). The title should read as a heading, level 1.
2. **Pages row.** Each tab says its date and "current page" on today's. The `×` says "Delete page ...". `+` says "New page".
3. **Sections.** Swipe to "Mindset" (any section). It should say "button, collapsed" or "expanded". Double-tap: it flips and
   says the new state. Food and Fitness should start expanded.
4. **Habits.** A dot says "&lt;habit&gt;, MON, button, not pressed". Double-tap turns it on ("pressed").
5. **Rename.** Open it from the top bar: VoiceOver should jump into "Rename tab, dialog". Swipe: it must **not** read the page
   behind. Close it: focus lands back on RENAME.
6. **Workout Coach.** Start a workout. "Workout Coach, dialog" and nothing from the page behind. Check a set: you should
   still be on that set's check ("Set 1 done, button, pressed"), not thrown to the top.
7. **Rest timer.** After a set you should hear "Rest 2:30" once. Swipe to Skip and stay on it for 5 seconds: VoiceOver must
   stay on Skip and not keep re-reading. You should hear "10 seconds left", then "Rest over. Go." Turn the ringer off
   and repeat: the spoken lines are the only alert, so this is the realistic gym test.
8. **Chips.** In coach settings, "Push / Pull / Legs" etc. say "pressed" or "not pressed". The gear says "expanded" / "collapsed".
9. **Toast.** Tap SAVE: hear "Saved". Trigger an error (offline, then an action that fails): it should interrupt.
10. **Reduced motion.** Settings > Accessibility > Motion > Reduce Motion on: the page jump to top and tab scroll must be
    instant, no sliding.
11. **Call Center, tabs.** Swipe to the tab row: it says "Call categories, tab bar". Only the selected tab is a stop; swipe
    right moves through the rest. With a hardware keyboard: arrows move and select.
12. **Call Center, chips.** Double-tap "Today". You should hear "Showing N people..." and focus must stay on "Today", not jump
    to the top. Pick dates: the date field keeps focus after you choose.
13. **Call Center, cards.** Each Play / Handled / Promise says whose ("Handled for Dana Smith"). Handle one: focus lands on
    the list, and you hear that the status changed.
14. **One at a time deck.** "…, dialog" is announced, focus lands inside, closing returns you to the button. Known gap:
    swiping can still leave it (see Left open).
15. **Dynamic Type.** Settings > Display > Text Size at the largest accessibility size: nothing in the sticky Today bar or the
    rest bar should be clipped.

Report back anything that differs from the lines above; each is a one-line fix in `a11y-ui.js` or the view file.
