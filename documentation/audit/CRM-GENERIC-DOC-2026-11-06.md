`document-generator.js` `renderGenericDoc` is the fallback for the **permit** type, which names a renderer that doesn't exist, and for any type whose template file isn't loaded. ED-F13 found four problems in it:

| What was wrong | Fix |
|---|---|
| "Details" printed **every** string field on the data object, including record ids (`leadId`, `userId`, `companyId`), internal notes and `_`-prefixed values. | Internal keys are skipped: `_`-prefixed, `…Id`, `uid` / `id`, and anything named "internal". Real fields such as Permit Number still print. |
| With no homeowner name, the title read "Permit Application — NBD Pro", putting PRO on customer paper. | It falls back to the company's name, then "Document". |
| The header brand line, the logo `alt` and the footer interpolated the company name, phone and website raw. | They are escaped with `_escHtml`. |
| The title interpolated the type name raw. | It is escaped. |

Earlier work already removed "Generated by NBD Pro" (#2943), and the colours are tenant-resolved. `docgen-render` (365), `docgen-brand` (35, the NBD byte-identity guard), `docgen-preflight-contract` (190), `customer-doc-branding` (17) and `tenant-paper-identity` (20) still pass.
