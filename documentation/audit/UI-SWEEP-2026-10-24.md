Jo, 2026-10-24: "sweep through everything we've got … more UI/UX improvements and also make
things cleaner, smoother, better." This is the first pass. It covers the CRM dashboard's 37 views,
driven through the sample account (`/pro/explore`, no login, zero network), at 390 px (phone) and
1280 px (desktop), on `main` `560b927` plus the unpushed audit-leftovers commits.

**Method:** a Playwright script opened each view with `goTo()`. On each one it recorded:
- horizontal page scroll, and elements wider than the screen outside a scrolling box
- controls under the target size: 24 px (WCAG 2.5.8 AA) everywhere, and 44 px (the house rule for phones, DESIGN.md)
- buttons with no accessible name, and inputs with no label
- console errors and failed loads

Screenshots were looked at by eye for the visual findings. The script and the screenshots stay in the session scratchpad, not the repo.

**Not covered yet:** the marketing site, `customer.html`, the portal, e-sign, the Success Tracker, and dark themes.
Those are pass 2.

## What is fine

- **No view scrolls the page sideways**, at either width.
- **No uncaught errors** came from app code. The only console errors were sample-account stubs, noted below.
- Every view rendered content. The four AI tool views were empty only because #2726 is not merged yet.

## Findings, ranked

### A. Accessibility: inputs with no label (Medium, mechanical)

About 30 inputs on 18 views rely on a placeholder alone. A screen reader reads a placeholder
inconsistently, and the placeholder disappears once someone types:

| View | Inputs |
| --- | --- |
| Pipeline | `crmDmgFilter` |
| Schedule | `spSearch`, `calBookingUrl`, `calFeedUrl` (+2) |
| Prospects | `pf-age`, `pf-attempts` |
| D2D | `d2d-addr-input`, the layer select |
| Photos | `photoSearchInput`, `photoLeadSelect` |
| Draw | `drawSearch`, `pitchSel`, `wasteSel` |
| Reports | `reportRangeStart`, `reportRangeEnd`, `reportCompareMode` |
| Ask Joe | `joeInput` |
| Visits (Talk Tank) | its search box |
| Products | `product-search` |
| Job Templates | `jtSearch` |
| Sunday review | `wrDecision` |
| Settings | 8 profile fields (`settingsName`, `settingsEmail`, `settingsCompany`, …) |
| Admin | `adminRosterFilter` |
| Home widgets | `w-task-input`, `w-ql-name`, `w-ql-addr` |

Money has one icon-only button with no name (`.mdx-btn-wrap`).

**Fix:** `aria-label` (or a real `<label for>`) on each one. No visual change.

### B. Targets under 24 px, the AA floor (Medium)

| Size | Control | View |
| --- | --- | --- |
| 13×13 | Checkboxes | Prospects, Photos, Draw, Reports, Settings, Home |
| 20×20 | Checkboxes | Job Templates select (107 of them) |
| 12×12 | Storm-zone chip | D2D |
| 41×12 | "Open →" | Schedule |
| 1×1 | Input | Home (probably a visually-hidden input that still takes focus) |
| 45×22 | Edit and Archive on every row (552) | Products, desktop |
| 23 px tall | Status chips (INS / CASH / FIN / WAR / SVC) | Pipeline, desktop |
| 21 px | Customer-name links | Catch up |
| 22 px | "MOVE TO COLLECTIONS" | Money |
| 14×18 | ✕ | Home, desktop |
| 10 px tall | "Set a goal" | Home, desktop |

**Fix:** a 24 px floor (padding or `min-height`), and larger hit areas on the checkboxes.

### C. Phone targets between 24 and 44 px (Low, design call)

Many phone controls are 30–40 px tall: tab rows (Storm, Academy, Settings), filter chips (Products,
Job Templates, Talk Tank), the "＋ NEW …" buttons and Pipeline's search and type filter. They pass AA but not
the house 44 px phone rule. Raising them all changes how dense every view looks, so this is **Jo's call**.

### D. Visual consistency (Low–Medium, by eye)

- **Product Library header buttons:** the four buttons are four colours: orange "+ Add Product", white
  "Price Book", **green "Export CSV"** and **red "Reset"**. Green and red are not brand button colours
  (DESIGN.md: orange primary, quiet secondary). A red primary-weight "Reset" also invites a mis-tap.
- **Storm Center (phone):** the stat cards row cuts off its third card at the screen edge, with no sign it scrolls.
- **Prospects (phone):** the Total / Hot / Warm / Cold tiles cut off "Cold" the same way.

### E. Sample account only (Low)

- **A raw function name** shows when a sample screen hits a server feature, e.g. `"callPipelineHealth" runs on NBD
  Pro servers…` and `"getAdjusterTacticBoard" runs on…`. The second one also names an insurance tool.
  The plain-words message should not name the function.
- **Money's Stripe card** prints "getStripeOverview" the same way.
- **Admin** logs a `listTeamMembers` console error.
