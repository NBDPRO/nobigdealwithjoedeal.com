# Authed E2E @shard2 red on main, 2026-10-12

**Scope:** `Authed E2E (emulators, @shard2)` failed on every `main` run from
`357cfead` (My Skin B1, #2334) through `60cb08a0`; it was green at `d5238507`.
Not a required check, but a red job that is always red hides the next real
regression. Root-caused by reproducing the shard locally (emulators + the
shard's own spec list, `PLAYWRIGHT_GREP=@shard2`) and by reading the CI traces.

## What was actually hard-failing

A "hard" failure is a test that failed all three attempts. The job's summary
lists them under `N failed`; the `N flaky` list passed on a retry and does not
turn the job red. The brief for this lane mixed the two, so the table keeps
them apart.

## The one real product bug

`my-skin.spec.js:41` "upload a wallpaper and mascot, survive a reload" was
**flaky** in CI (passed on retry) but it is a real race, introduced by #2334.
`NBDMySkin.upload()` used to call `save()` before painting. B1 changed it to
`showCurrent().then(function () { save(); })`: the settings write now starts
only after the paint finishes, and `upload()` resolved (and toasted "saved")
without waiting for it. A reload that landed in that gap came back with no skin
(the CI screenshot shows the plain Home page). Proved with a slowed `setDoc`
(2.5 s): old code loses the skin on reload, new code keeps it.

Fix (`docs/pro/js/my-skin.js`): start `save()` first, as before B1, and let
`upload()` resolve only when the write settles, capped at 5 s so an offline
phone never wedges the button. A new third test in `my-skin.spec.js` pins the
order with the slowed write (it fails on the old code at the reload wait).

`phone-numbers:145`, `phone-deal-packet:174`, `invoice-reminder:27`,

## How to repeat

```bash
cd tests
PLAYWRIGHT_BASE_URL=http://127.0.0.1:5000 PLAYWRIGHT_TEST_USER_EMAIL=playwright-e2e@nbd.test \
PLAYWRIGHT_TEST_USER_PASSWORD=nbd-e2e-password-1 PLAYWRIGHT_GREP=@shard2 \
env -u HTTPS_PROXY -u https_proxy -u HTTP_PROXY -u http_proxy npx firebase emulators:exec \
  --only auth,firestore,storage,hosting --project nobigdeal-pro \
  "node ./e2e/fixtures/seed-emulator.js && node ./e2e/fixtures/run-authed-specs.js"
```

(`npm run test:e2e:authed:emu` does not run under cmd.exe on Windows: the
`${NBD_EMU_FUNCTIONS:+,functions}` expansion is not valid there.)

Lessons: a new E2E spec that has only ever run in CI is untested; the shard
shares one rep, so any spec that leaves state (a scheduled lead, a company
lock, a skin) can fail the specs after it; and two specs that "wait for" a
lazy global must load the bundle themselves.
