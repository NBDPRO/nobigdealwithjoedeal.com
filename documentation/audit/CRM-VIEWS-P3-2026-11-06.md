# CRM views P3 batch — 2026-11-06

Part of the [overnight CRM audit](CRM-AUDIT-HARNESS-2026-11-06.md). There are seven small fixes in this batch. Each has a check in `tests/views-p3-2026-11-06.test.js` that runs the shipped code. The suite passes 21/21 with the fixes and fails 15 of 21 against main.

| Finding | What was wrong | Fix |
|---|---|---|
| VW-F110 | On a failed read, photo review put `err.message` into `innerHTML` unescaped (`pages/photo-review.js`). | The message now goes through the file's own `esc()`. |
| VW-F164 | The Thursday widget's empty state printed NBD's Thursday number, (513) 940-5589, for every company (`widgets.js`). | NBD (`_isNbdPlatformTenant()`) still sees the number. Every other company reads "your business line". |
| VW-F165 | A failed `getAiTextingStats` call returned `null`, so the card said "No AI reply drafts yet" (`ai-texting-stats-card.js`). | A failure now returns `{ _failed: true }`. It is not cached, so the next open retries. The card says it couldn't load. |
| VW-F108 | Social Studio: the settings listener had a no-op error callback, so a failed read left the panel on defaults, and one tap saved those defaults over the stored settings. The AI caption pass also swallowed failed writes and still reported "(AI caption)" (`pages/social-studio.js`). | A failed read now toasts and locks the toggles. Failed caption writes are counted and named in the drafts toast. |
| VW-F109 | Project Codex: save and load swallowed every error (`ai-tool-finder-page-2.js`), so full or corrupt storage dropped progress silently. | Both now show an error toast. |
| VW-F163 | The CSV import modal had no Escape key. Its drop zone was a non-focusable div, and the file input is hidden, so a keyboard user could not pick a file (`data-import.js`). | The drop zone is now `role="button" tabindex="0"` with a label, and Enter or Space opens the picker. The modal calls `nbdOverlay.attach` (the shared contract in `overlay-a11y.js`), which gives it Escape, a Tab trap and focus return. |
| VW-F168 | The installed app's description in `docs/pro/manifest.json` was "No Big Deal — Roofing CRM Dashboard" for every company. | It is now "Roofing CRM dashboard". The app name (NBD Pro) is unchanged. |

**No new inline styles.** The ratchet ceiling is still 2079. The failed state reuses the empty state's markup with different text.

**Not built: VW-F111.** `refer.html` defaults to NBD's title until `?co=` says otherwise. The fix the audit suggests, a neutral default title, would also change NBD's own referral page, which is brand copy, so it is logged in DECISIONS rather than shipped overnight.

**Not built: VW-F160.** The keydown listener in the `standalone-compat.js` dialog leaks, and the dialog has no focus trap. That file loads parser-blocking in `dashboard.html`, and the boot budget (`dashboard-boot-budget-2026-10-03`) has about 13 bytes of headroom, so any real fix trips the gate. It needs either a budget decision or a move of the dialog code out of the blocking file.

**Not in this batch:** the Thursday widget's read catch still only logs (`widgets.js` ~1063). On a failed read the widget stays on its loading state rather than showing the empty state, so it does not mislead. It is left for a follow-up.
