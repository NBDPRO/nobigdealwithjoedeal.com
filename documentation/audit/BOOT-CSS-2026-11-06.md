# Boot CSS: 41 dashboard stylesheets made late (2026-11-06)

Lane: step 4 of [NEXT_SESSION-2026-11-04-site-crm-speed](../projects/NEXT_SESSION-2026-11-04-site-crm-speed.md)
("Boot CSS, measured, not built"). Branch `claude/boot-css-late-sheets`.

## Result in one paragraph

41 of the dashboard's 69 linked stylesheets (1,696 of 6,308 rules, 218 KB readable) style nothing on the first
screen for any role, layout or width. They now ship as `<link rel="stylesheet" media="print" data-late-css>`, and
`docs/pro/js/late-css.js` removes the `media` attribute on the first tap or key, on any `goTo()` but Home, at once
for a `?query` link, or when the page goes idle after load (2 s at most). **On a cold load over a slow phone link
first paint is 1.7 s sooner** (7.96 → 6.28 s; render-blocking CSS files 56 → 21). **The CPU win the 11-04 note
expected is not real:** boot style recalculation is the same with the sheets late, and the same with them deleted
outright. On this dashboard restyle cost does not follow rule count.

## How it was measured

Chrome's CSS rule-usage tracking (`CSS.startRuleUsageTracking` over CDP) from the start of a dashboard load until
the page had settled (data loaded + 6 s). A sheet counts as "used at boot" if any rule in it matched anything.

| Run | Account | Matrix | Boots |
|---|---|---|---|
| Roles | Emulator rig, seeded empty tenant: owner (`company_admin`), `manager`, `sales_rep` (loads the canvasser bundle), `viewer` | 8 layouts × phone 390 / desktop 1440 | 64 |
| Data | Sample account (`/pro/explore`, the full demo data set) | 8 layouts × phone / desktop | 16 |

All 80 boots succeeded. 97 stylesheets were seen (including lazy bundles); 40 were used by at least one boot,
57 by none; 48 of the 57 are linked eagerly by `dashboard.html`.

Re-measure on the sample account with `node scripts/measure-boot-css.js` (it measures late sheets as if they were
eager and exits 1 when one marked `data-late-css` is used at boot). The role matrix needs the emulator rig
(`tests/e2e/fixtures/seed-emulator.js`, extra users with `{ companyId, role }` claims; the scratch script that ran
it was not committed).

## Kept eager although unused in the runs

Seven of the 48 stay plain stylesheets, because what they style depends on state a real account can have at boot
that the runs did not have:

| Sheet | Styles |
|---|---|
| `theme-art.css` | `:root[data-theme=…]`: a saved non-default theme |
| `shape-styles.css` | `:root[data-shape]`: a saved shape style |
| `field-sunlight.css` | `html.sun-all`: sunlight mode |

| `d2d-tracker.css` | `body[data-nbd-size]`: text size |
| `offline-sync.css` | the offline badge (a boot while offline) |
| `pwa-install-nudge.css` | the install prompt (can fire at boot) |

The dark-flag header buttons (Speed to lead, Follow-ups, Estimate follow-ups, Reputation, Lead sources, Stale
leads) live in the Pipeline view's header, not on Home, so reaching them goes through `goTo('crm')`, which applies
the late sheets first.

`tests/late-css-2026-11-06.test.js` pins both lists: a sheet moving on or off the late list is a deliberate edit.

## Why `media="print"`, not `rel="preload"`

The first build used `<link rel="preload" as="style">` and flipped `rel`. In the browser that failed twice:

1. Under a service worker Chrome does not reuse the preload ("cross-world service worker resource mismatch"): every
   late sheet downloaded a second time on the flip. The real CRM runs under `/pro/sw.js`.
2. The flip waited on that fetch (about 200-350 ms), so a view opened by `goTo()` before idle painted its first
   frame unstyled (11 of 12 views tried).

A `media="print"` stylesheet is downloaded once and parsed, does not block rendering and stays out of screen
restyles; removing `media` applies the already-parsed sheet at the next restyle. After the switch: 0 of 41 late
sheets unapplied on the first frame of any of the 12 views (expenses, money, storm, closeboard, reports,
job-templates, signs, repos, crm, settings, docs, calls), with idle disabled to force the worst case; no late sheet
fetched again; 0 page errors. Each `<link>` keeps its place in the document, so the cascade order is unchanged.

## Numbers

**Style recalculation at boot** (sample account, phone, warm worker, 4× CPU throttle, reload until data + 1.5 s,
alternating runs):

| Build | RecalcStyle ms (6 runs) | Median |
|---|---|---|
| `main` | 826, 793, 892, 817, 717, 808 | ~812 |
| branch | 837, 819, 774, 757, 922, 828 | ~823 |
| branch, idle flip disabled | 719, 821, 975, 934, 682, 1026 | ~878 |
| the 41 links deleted (control) | 917, 938, 837, 958, 1115, 838 | ~928 |

No difference beyond run-to-run noise, even with the sheets gone. The 11-04 estimate ("each restyle about 40 %
cheaper") assumed restyle cost scales with rule count; it does not here. What does drive it is open (DOM size,
invalidation from boot-time class/attribute writes, `:has()`, custom properties are the usual suspects).

**Cold load, slow link** (emulator rig, owner, phone, service worker blocked, cache disabled, 150 ms RTT,
1.6 Mbps down; 4 runs each, medians):

| Build | First paint | FCP | DOMContentLoaded | load | Render-blocking CSS |
|---|---|---|---|---|---|
| `main` | 7.52 s | 7.96 s | 25.2 s | 25.2 s | 56 |
| branch | 5.88 s | 6.28 s | 23.6 s | 25.3 s | 21 |

All 41 late sheets were downloaded and parsed by the load event on that link, and a `goTo('expenses')` after it had
every late sheet applied on its first frame.

## Edge cases

- A deep link (`#/expenses`, `?agentInbox=1`) on a slow first visit can open its view before the late sheets have
  arrived: they apply as each one lands (a normal non-blocking stylesheet load), where before they held up the whole
  first paint.
- `customer.html` was not measured and is unchanged.
- Printing the dashboard before the flip would include the late sheets' rules (print media). Harmless.
