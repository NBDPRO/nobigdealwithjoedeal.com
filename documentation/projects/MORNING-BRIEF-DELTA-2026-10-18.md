# Morning brief delta mode (2026-10-18)

Step 1 of the notification policy (draft policy note: PR 2527,
`NOTIFICATION-POLICY-2026-10-18.md`, three tiers: interrupts, one delta-only
morning brief, a Sunday review). The 06:45 brief was the bloat in a week of
`jd@` mail: about 17 KB a day, repeating the same signed-job names and an
open-promises list of 17 to 47 that never shrinks. This adds a **delta mode**
behind a flag that ships **off**.

## What the brief contained (before)

`functions/morning-brief.js` (reads) + `functions/morning-brief-logic.js`
(pure render). One email to the owner (Jo), 06:45 ET:

1. **Appointments today**: Cal.com bookings, job days (multi-day on their
   middle days), adjuster meetings, CRM-booked events; each with stage, other
   jobs, last activity, open balance (cents), storm history, a "Brief me"
   one-liner and a forecast line on job days.
2. **Signed jobs that need a week** (`production-flow-logic.needsWeek`): a
   name list of up to six plus a Plan Jobs link, every day.
3. **Absorbed sections** (`MORNING_BRIEF_ABSORB_ENABLED`): new leads in the last
   24 h, "you said you'd…" (up to 15 rows), repeat unknown numbers, review asks
   ready (up to 15).

## What delta mode does (flag on)

| Part | Flag off (today) | Flag on |
|---|---|---|
| Appointments | full | full, unchanged |
| New leads (24 h) | listed | listed, unchanged (already a delta) |
| Promise-read warning, repeat-number line | shown | shown, unchanged (a failure is never collapsed into an all-clear) |
| Signed jobs needing a week | names, daily | names only for NEW ones; otherwise a count line + Plan Jobs link |
| Open promises | up to 15 rows, daily | rows only for NEW ones, or ones that turned URGENT; otherwise a count + Call Center link |
| Review asks | up to 15 rows | rows only for NEW ones; otherwise a count |
| Subject | counts of everything | the appointments line + only what is new, or `nothing new` |

A "standing" count line reads like `17 open promises (3 new, 2 cleared)` or
`8 signed jobs need a week (no change)`. A count passing **10, 25 or 50**
(upward) also counts as news and says `passed 25`.

If nothing is new the brief **still sends**, short: the appointments line plus
three count lines. (Jo's task brief said so; the policy note's "quiet means
silent" would argue for skipping it. See Decisions.) A day with no
appointments and nothing at all to say is still silent, as before.

## The snapshot

`morningBriefState/{companyId}` (the owner's uid for NBD): `{ companyId,
updatedAtMs, snapshot: { v:1, atMs, lists: { needsWeek|promises|reviewAsks:
{ atMs, ids[], urgent[] } } } }`. **Ids only**: lead ids, `callId`s, review-ask
lead ids. No name, phone, address or promise text. Capped at 500 ids a list.

- Written (`set` with merge) **only after a live, accepted send**. A dry run or
  a rejected Resend response never advances it.
- `firestore.rules`: `allow read, write: if false` (Admin SDK only). A client
  that could write it could hide items from the owner's brief.
- Read with a tenant check (`companyId` must equal the owner) and fails safe:
  missing, unreadable, malformed, wrong tenant, older than 72 h, or a list the
  snapshot lacks all mean **show that list in full**, exactly like today. Delta
  mode can only show less when it has positive evidence of what was already seen.
- A failed promise read leaves `promises` out of the written snapshot so
  yesterday's good entry survives the merge.

## How "flag off is unchanged" is proven

`tests/fixtures/morning-brief-flag-off-golden.json` was generated by running five
scenarios through the **original** `morning-brief-logic.js` (before any edit).
The test asserts `buildBrief` output (subject, html, text, sendable, item keys,
counts) is identical for each, with `delta` absent and with `delta: null`, and
that a full run with the flag absent, `false` or `yes` sends the same bytes and
never touches `morningBriefState`.

## Decisions and open points for Jo

- **Send on a quiet day?** Built as asked: still sends a short brief when
  something standing exists. The policy note says "quiet means silent"; if Jo
  prefers that, it is a one-line change in `buildBrief` (`sendable`).
- **15:15 promise sweep.** The brief still stamps the promise list it saw
  (`stampDigest`), so the 15:15 email is still skipped when the list is
  unchanged. Retiring that email is policy step 3, not this PR.
- **New leads** have no id in `gatherDigestRows`, and a 24 h window is already
  "since yesterday's brief", so they are not tracked in the snapshot.
- Pre-existing quirk, untouched: when promise reads fail and nothing else
  exists, the flag-off subject ends `no appointments — ` with an empty tail.
  Delta mode says `nothing new` instead.
- **Turning it on** is Jo's call: set `MORNING_BRIEF_DELTA_ENABLED=true` in
  `functions/.env.nobigdeal-pro`, merge, deploy. The first brief after that is
  the full one (no snapshot yet); the second is the first delta.
