## Section 3: Notes

- **Which lead the page shows, and whether a save can hit a different one:** the id is read once from `?id=` (customer-bootstrap.module.js:320-323). `window._customerId` is set once (bootstrap:533). Its only other writer repo-wide is dashboard-bootstrap.module.js:1047, which this page does not load. The Messages and Voice mounts capture the leadId when they mount. Every save reads `window._customerId`. Links to another lead (referred-by, calls "Open them" / new lead) do a full page load, and a bfcache restore forces a reload (bootstrap:236-241). **No path writes to a lead other than the one displayed.** The integrity risks are within the lead: stale in-memory copies (CU-F04) and index-based photo writes (CU-F03).
- **onSnapshot:** this page has only two: portal_messages and recordings. Both unsubscribe on `beforeunload`, and the page is not an SPA. Leads have no listener, so other modules hand-repaint after writes.
- **`textContent =` on elements with children:** the upload buttons were fixed with sibling-span toggles (`_setDocUploadBusy` photo-report-generator.js:197-204, `_setPhotoUploadBusy` bootstrap:3137-3144). I found no remaining `textContent =` on an element whose children are needed. The other writes (doc-btn, saveEditBtn, copyBookingBtn, comm-stop) are on text-only buttons. `#repMsgThread.innerHTML` on a snapshot error does destroy its `#repMsgEmpty` child (CU-F17).
- **Doc-upload dedupe** on name+size+lastModified is present (customer-photo-report-generator.js:64-85). It is what hides the double-bound listeners (CU-F14). It does not stop re-sending the stale queue (CU-F01). The page never freezes: there are no native dialogs on this path and progress shows per file.
- **Approved additive feature gaps:** CU-F06 (phoneDigits fallback for `phone_calls`, Tier A) and CU-F07 (Drive folder URL field, Tier A).
- **Not on this page:** `customer-photo-hub.js` and `customer-estimate-hub.js` load only from dashboard.html:6360-6361. The internal estimate hub UI belongs to the dashboard slice, and the photos section here is customer-tasks-ui.js.
- **Not read in depth (scored `?`):** production.js, claim-core/insurance-claim, profit-tracker, warranty-claim, promise-ui, lost-reason/numbers, the snooze/consent/lien/AI-drafts/smart-follow-up/lead-score panels, and customer-photo-report-picker internals. Other slices own these.
- **Portal message unread badge** clears only when the rep replies (functions/portal-reply-effects.js:52-57), not when the rep views the thread. That matches the design but is worth knowing.
- **Storage hygiene:** photo deletes (single and bulk) delete the Firestore doc only, so the Storage object is orphaned. Uploaded documents store a `getDownloadURL` token URL as `url` (customer-photo-report-generator.js:233-241, customer-signed-doc-upload.js:46-51). Generated docs moved off token URLs for the same reason. Tier C, propose only.
